# ADR 0003: Gate 1 — the scoreboard is fixed; pass once the stamped commit is public

Date: 2026-11-16        Status: accepted (by the project owner, 2026-11-16)

## Context

Gate 1 (blueprint 16.3) passes if the baseline report reproduces, the split and threshold are
committed, and the pre-registration is timestamped. It has no scientific stop condition. Scope is
the Amazon + Cerrado region and forest loss (ADR 0002, docs/phase1/PLAN.md). Evidence:

| Condition | Evidence | Met |
|---|---|---|
| Baseline report reproduces | `docs/phase1/baseline_report.md`, generated at `7be6287` on a clean tree; an independent run from `fa04238` matched all 1,668 numbers (`tools/phase1/compare_reports.py`) | Yes |
| Split committed | `configs/splits/amazon_cerrado_v1.csv`; no training tile touches a scored tile | Yes |
| Threshold committed | `configs/thresholds/amazon_cerrado_v1.json`; study in `docs/phase1/THRESHOLD.md`, reproduces bit for bit | Yes |
| Pre-registration timestamped | Bundle `761aca4a…` (82 files, commit `ed2cf4f`): FreeTSA and DigiCert RFC 3161 tokens at 2026-11-15 19:05 UTC, both verified from a fresh clone; OpenTimestamps submitted, awaiting Bitcoin confirmation (`docs/prereg/2027.01.record.md`) | Yes; Bitcoin anchor pending |
| Public commit (task 1.13 acceptance test) | Published 2026-11-16, [https://github.com/pranavpanchal1326/Almanac](https://github.com/pranavpanchal1326/Almanac) | Yes |

What the numbers say (forest-loss task, average precision; base rate in brackets):

| Set | B2 last change | B3 proximity | B4 trees |
|---|---|---|---|
| Validation 2024 (0.066) | 0.089 | 0.200 | **0.246** |
| Test 2025 (0.035) | 0.063 | 0.160 | **0.315** |
| Held-out region 2025 (0.051) | 0.214 | 0.283 | **0.549** |

B4 is the reference. To win, the model needs at least 0.295 on validation-like data and
roughly 0.38 on test-like data, plus the guard: better than B4 on test tiles and on the held-out
region separately.

## Decision (proposed)

1. Gate 1 **passes on the scientific and reproducibility conditions**. The split, threshold, event
   definitions, reference baseline and win condition are fixed by the pre-registration and do not
   change.
2. The gate is **formally closed when the stamped commit `ed2cf4f` is public**. Until then, Phase 2
   may write and test model code and specify the model in section 10 of the pre-registration,
   but **no model is trained** on this region. Training before publication would leave a gap in the
   record that outsiders cannot check: the timestamps prove the bundle existed, but not that it
   was disclosed.
3. The OpenTimestamps proof is upgraded and committed once a Bitcoin block includes it. The RFC 3161
   tokens already satisfy "two timestamp authorities"; the Bitcoin anchor is the independent third.

**Closed 2026-11-16:** the stamped commit `ed2cf4f` is public, so decision 2 is met and Phase 2
may train models under the pre-registration's rules.

## The opposite case, argued

**"Gate 1 should not pass: the scoreboard is unfair to the model."**

- *B4 may be too strong because of leakage.* Answered: a test changes every input from the target
  year onward and checks that features and scores do not move (`tests/unit/test_baselines.py`);
  the held-out region was never in training; training tiles that touch scored tiles are dropped.
  B4 is strong because past loss nearby predicts loss, which is the known fact the blueprint
  warned about (3.6), not a leak.
- *The validation year is abnormal (2024 fires, 1.5 times the usual loss).* True. B4 is also best
  on validation 2023 (0.216 against 0.129), so the choice of reference does not hinge on 2024.
  The risk stays for the model's own choices and is stated in the pre-registration.
- *The interval method is optimistic.* True, shown in simulation (65% coverage of AP at 60
  tiles). The guard was added for this reason. It does not make the interval exact.

**"Gate 1 should not pass: the scoreboard is unfair to the reader."**

- *The forest mask is unvalidated.* True: forest extent from tree cover 2000 was not checked
  against published forest area. The label's loss totals match the source within 0.2%; the mask
  only decides which cells are eligible. Open item below.
- *The test year has been read twice.* True, both runs of the same baselines, both logged. The
  model family has not touched it.
- *Nobody outside the project has reviewed anything.* True. The pre-registration says so. A
  public commit is the cheapest way to change that, and decision 2 depends on it.

**"Gate 1 is beside the point: the project should stop."** Gate 1 has no stop condition, and
the baseline report is already a useful public product (blueprint 16.3 note). The real test is
Gate 2. What has changed is that the bar is high: if no model clears B4, the plan already says
to lock B4's forecast as issue 2027.01 (blueprint 16.4, "Fail").

## Consequences

- Easier: Phase 2 starts against fixed rules; nothing about the exam can be adjusted after
  seeing a model's score.
- Harder: the model must beat a tree ensemble that already uses neighbourhood loss at three
  radii, with no drivers. Phase 2's ablation of drivers (2.5) has no drivers to ablate until task
  1.6 is unparked.
- Watch: the 2025 layer's shift (Phase 0), the upward drift in embedding change (THRESHOLD.md),
  and whether a model's gain survives the guard.

## First three tasks of Phase 2

1. **2.1** Dataset class and seeded, balanced sampler over the region store (training tiles,
   target years 2019–2023).
2. **2.2** Model S smoke test: overfit one batch; record memory and throughput on the RTX 5060.
3. **2.3** Baseline B5 (per-cell temporal model, no neighbours), scored on validation before any
   full model is.

The model specification for section 10 of the pre-registration is written before task 2.4.

# Pre-registration 2027.01 — amendment 1: the model

Written 2026-11-16, before any model was trained. This is section 10 of the pre-registration,
kept as a separate file so that the stamped text of `2027.01.md` stays byte-for-byte verifiable.
It is timestamped on its own (`docs/prereg/proofs/2027.01.amendment-1.*`). Nothing here changes
sections 1–9: the task, data, split, event definitions, reference baseline (B4), win condition
and grading stay as stamped.

## 1. Family

The network in `src/almanac/model/net.py` (blueprint 15.3, adapted): per cell, the last `K` = 5
years of embeddings plus one query position for the target year; `L` blocks of temporal attention
across the `K` + 1 positions, 3 × 3 depthwise and pointwise spatial mixing, and a feed-forward
layer of width `4d`; pre-normalisation, GELU, dropout 0.05, 4 attention heads.

Inputs per history year: the 64 embedding values, forest lost that year, any loss that year, and
whether that year's label exists; a learned "absent" token where the year is missing or hidden.
Inputs per cell: forest at the start of the target year, land share, loss before 2018, cumulative
loss up to the issue year. These are the same facts B4 receives. No drivers (task 1.6 is parked)
and no location features, so the model cannot memorise places.

Outputs from the query position: a forest-loss logit (primary), an embedding-change logit
(secondary) and the target-year embedding as a mean and a spread (auxiliary).

Horizon 2 and readout heads of blueprint 15.3 are dropped: the exam is horizon 1, and the forest
head is the readout.

## 2. Size

Model **M**: width 192, 8 blocks (receptive field 8 cells, about 5 km). Model S (128, 6) is used
only for tests and the smoke test. L is not used for this issue.

## 3. Data and sampling

- Training tiles only (800), target years **2019–2023**: the same tiles and years the baselines
  were fitted on. Exam tiles (test and held-out) are never used for training, at any stage.
- Patches of 32 × 32 cells; half of the patches contain at least one forest-loss event in the
  target year, half are uniform over patches with any eligible forest cell; origins on a 16-cell
  grid, shifted at random by up to 8 cells.
- Augmentation: flips and quarter turns; with probability 0.5 the earliest `j` years are hidden
  (`j` uniform in 0–4); with probability 0.15 one random year is hidden.
- Eligibility, events and inputs are those of the baselines (`src/almanac/model/store.py`;
  identity with `src/almanac/baselines/features.py` is tested on real tiles).

## 4. Losses

Binary cross-entropy for forest loss (weight 1.0) and for embedding change (0.5); Gaussian
negative log-likelihood of the target embedding, spread floor 1e-4 (0.1). Each term is averaged
over its eligible cells; ineligible cells contribute nothing.

## 5. Optimisation

AdamW, gradient clip 0.5, bfloat16 mixed precision, exponential moving average of weights 0.999
(the averaged copy is the one evaluated and kept). Two schedules are compared, both with weight
decay 0: (a) constant 1.1e-4; (b) peak 3e-4, 1,000 warm-up steps, cosine decay to zero.

Set from the task 2.2 measurement by rules fixed now:

- **Batch:** 16 patches if peak GPU memory at 16 is below 6.4 GiB (80% of the 8 GiB card),
  otherwise 8.
- **Steps per run:** the largest multiple of 2,000 that fits 8 hours at the measured step time,
  capped at 100,000. Validation every 2,000 steps.

## 6. Selection on validation (stage A)

Order, fixed in advance:

1. **B5** (the same network with spatial mixing removed, schedule (a), seed 1) is trained and
   scored on validation 2024 first, so it joins the candidates for the reference (pre-registration
   section 4). If B5 beats B4 on validation 2024, B5 becomes the reference.
2. Model M with schedules (a) and (b), seed 1 each. The schedule with the higher validation 2024
   forest-loss AP is chosen. A tie within 0.002 goes to (a).
3. The chosen schedule is trained with seeds 2 and 3.
4. For each run the kept weights are those at the validation check with the highest validation
   2024 forest-loss AP.

Validation scoring uses every eligible cell of the 146 validation tiles, predicted tile by tile
with overlapping 32-cell windows (`src/almanac/model/infer.py`), scored with the same code as the
baselines.

## 7. The forecast that is graded

- **The model's forecast is the mean of the forest-loss probabilities of the three seeds** of the
  chosen schedule, each mapped to a probability by isotonic regression fitted on its own
  validation 2024 predictions. AP is unchanged by that mapping; it matters only for the Brier
  score, log loss and calibration, which are secondary.
- **Backtest (stage B):** this frozen ensemble is scored once on test 2025 and held-out 2025, and
  the touch is logged in `docs/phase1/test_touch_log.jsonl`.
- **Forward (the exam):** the same frozen weights, with inputs up to 2025, forecast 2026. **There
  is no refit on later years.** This departs from blueprint 15.7 (stage C) on purpose: the
  reference B4 was fitted on 2019–2023 only, so a model refitted on 2019–2025 would have seen two
  more years of data than the baseline it is compared with.

## 8. What is not allowed after this amendment

- Changing the architecture, size, inputs, losses or sampling after any model has been scored on
  validation. A change means a new amendment and a new model family, and the earlier runs are
  reported anyway.
- Any run that reads the 2025 test truth other than the single stage B evaluation.
- Ablations (task 2.5) are reported on validation only and cannot change the forecast.

## 9. Configuration

`configs/model/stage_a_b5.json`, `configs/model/stage_a_m_a.json`, `configs/model/stage_a_m_b.json`.
Their SHA-256 at this amendment are in the amendment's bundle. If the task 2.2 rules change the
batch size or step count, the configurations are updated by those rules only, before the first
training run, and the updated digests are recorded in `docs/phase2/STATUS.md` with the
measurement that produced them.
